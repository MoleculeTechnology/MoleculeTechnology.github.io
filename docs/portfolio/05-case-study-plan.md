## Paper Ghost — software that became part of the set

**Purpose:** Establish spatial experience, visual authorship, and delivery alongside film crews.
Make this a flagship story rather than an abbreviated employment entry.

The existing About page provides several distinct examples:

- **X-Men: Apocalypse:** Pentagon video wall and retro computer/CRT visuals.
- **The Glass Castle:** Rear projection playback software for studio car scenes.
- **Quantico:** Interactive prop screens, actor-operated phone apps, surveillance stations, and timers.
- **mother!:** Set previsualization and virtual rehearsal tooling.
- **Arrival / Ça Décolle!:** Additional screen or real-time environment work as supporting examples.

Start with one spatial scene and two supporting examples.
The Glass Castle is particularly relevant to installation work because the software, projection, camera, physical space, and operator must work together.
The existing photo `glasscastle_test4.jpg` is a candidate for a setup image, not a selected final hero until visually reviewed.

**Story arc:** What the scene needed to achieve → what actors/camera/operators needed → visual and software decisions → what Russell delivered → collaborators and result.
Describe aesthetic choices as carefully as technical choices.
Ask how interfaces were composed for camera, how imagery supported the scene, and what had to be responsive or adjustable on set.

**Diagram:** Operator input → visual/playback software → projection or prop screens → set/camera.
Mark Russell's contribution and Zed Axiz's hardware/set operation contribution separately.

**Evidence to collect:** Usable scene clip, wide setup photo, interface detail, role confirmation, project dates, collaborator credits, and one production constraint with an example of its resolution.
Possible LinkedIn project names OLOSCAPE and OLOSET should be confirmed before use.
Do not imply sole authorship of the film's visual world or physical equipment.

## Molecule — light and motion in a physical object

**Purpose:** Show current artistic authorship and the growing ability to connect hardware, software, and visual output.
Present the light sword as a real creative object and ongoing investigation.

**Story arc:** Desired gesture/light relationship → physical design and implementation → tuning response and visual behavior → demonstration → current limitations and next iteration.
Ask what Russell wanted the light to feel like and why the object takes its form.
The visual result should lead. Firmware details should explain a decision that matters to the result.

**Source evidence:** Saga contains light/sensor firmware and multiple board profiles.
Keep board-specific behavior separate until the current physical configuration is documented.
Do not generalize one board's features to every version.

**Media:** Full object in darkness, object in ordinary room light, a person using it, sensor/LED detail, and a diagram connecting input to output.
Capture current actual behavior, including latency or recovery only if measured.
Confirm electronic design, assembly, enclosure, software, and artistic responsibilities individually.

## Possible new artwork, not existing portfolio evidence

**Working concept: A field of light.**
Explore a small group of light elements whose timing or intensity responds to a visitor's gesture.
Define one expressive rule, such as a movement leaving a slowly fading spatial trace, before choosing more sensors or effects.
Start with one working element, test how understandable the response feels, and then decide whether multiple elements strengthen it.

This is a proposed direction for creating new authored work.
The title, visual form, sensing method, venue, and feasibility remain undecided.
It must never appear among completed projects without a clear concept/prototype label.
